# Task 1：从 C 源码到可执行文件

一个 `.c` 文件要变成能直接双击运行的程序，中间要经过四个阶段。以 `main.c` 为例：

**1. 预处理（preprocessing）**
处理所有以 `#` 开头的指令：把 `#include` 的头文件内容原样展开进来、把 `#define` 的宏做文本替换、按 `#if` 之类条件决定保留或丢弃哪些代码、去掉注释。产物仍然是 C 源代码，一般叫 `main.i`。
对应命令：`gcc -E main.c -o main.i`（`-E` 就是只做预处理）。

**2. 编译（compilation）**
把预处理后的 C 代码翻译成汇编代码，也就是把“人能读”的语言变成“接近机器”的语言，并在这个过程中做语法检查、类型检查和一些优化。此时还没变成二进制机器码，产物是 `main.s`。
对应命令：`gcc -S main.i -o main.s`。

**3. 汇编（assembling）**
把汇编代码逐条翻译成 CPU 能执行的机器指令，生成**目标文件** `main.o`。目标文件里已经是二进制机器码，但地址还没确定：它引用的 `printf`、`log_message` 之类的函数都只是“待填的空位”，不能单独运行。
对应命令：`gcc -c main.s -o main.o`。

**4. 链接（linking）**
链接器把所有目标文件（`main.o`、`calculator.o`、`logger.o`……）以及用到的库（如标准库 libc）拼在一起，把那些空位填成真实地址，最终生成可执行文件 `calculator`。
对应命令：`gcc main.o calculator.o logger.o -o calculator`。

一句话总结：**预处理整理源码 → 编译变成汇编 → 汇编变成机器码（目标文件）→ 链接把目标文件和库拼成可执行文件**。前三个阶段都是“一个源文件对一个产物”，只有链接是把多份产物合成一个程序，这也是为什么多文件项目最后一步总是链接。
